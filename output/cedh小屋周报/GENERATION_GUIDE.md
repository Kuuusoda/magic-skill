# cEDH 小屋周报生成指引

本文档定义 cEDH 小屋周报的标准化生成流程，确保每周报告格式一致、数据准确、分析有深度。

---

## 一、报告目的

- 追踪近两周 cEDH 赛事环境变化
- 识别环境占比趋势和新兴套牌
- 深度拆解夺冠的非主流套牌，提供构筑参考

---

## 二、数据来源

**主数据源**: [Topdeck.gg](https://topdeck.gg) API

- 接口: `https://topdeck.gg/api/v1/tournaments`
- 筛选参数:
  - 赛制: `EDH / Commander`
  - 时间范围: 近 14 天
  - 参赛人数: ≥ 50 人（周报只收录有统计意义的中大型比赛）
- 补充数据: 各比赛官方报道、冠军采访、套牌 Primer

---

## 三、生成步骤

### 步骤 1：获取原始数据

调用 Topdeck.gg API 获取近 14 天所有 EDH 比赛，提取以下字段：

| 字段 | 说明 |
|------|------|
| 日期 | 比赛举办日期 |
| 比赛名称 | 完整名称 |
| 参赛人数 | 总参赛人数 |
| 冠军 | 冠军选手姓名 |
| 冠军套牌 | 指挥官组合（中文官方译名） |
| Top 16 | 100 人以上比赛需记录 Top 16 详情 |

### 步骤 2：数据清洗与筛选

- 剔除参赛人数 < 50 的比赛
- 统一套牌名称（使用 `name_translator.py` 确认中文官方译名）
- 标记 "N/A"（数据缺失的比赛）

### 步骤 3：生成概览表

**表 1：所有 50 人以上比赛概览**

```markdown
| 日期 | 比赛名称 | 人数 | 冠军 | 冠军套牌 |
|------|---------|------|------|---------|
```

**表 2：100 人以上比赛 Top 16 详情**

为每场 100 人以上的大型比赛单独生成 Top 16 表格：

```markdown
### YYYY-MM-DD — 比赛名称 (人数)

| 名次 | 选手 | 套牌 |
|------|------|------|
```

### 步骤 4：环境统计分析

统计所有比赛的环境占比，生成 **Top 15 套牌出现频率表**：

```markdown
| 套牌 | 出现次数 | 占比 |
|------|---------|------|
```

### 步骤 5：识别"小屋严选"候选

**候选标准**（满足任一即可）：

1. **夺冠的非主流套牌**: 环境占比 ≤ 2% 但获得了冠军
2. **进入 Top 4 的冷门套牌**: 环境占比 ≤ 1% 但进入了前四名
3. **连续两周表现突出的新兴套牌**: 出现频率环比上升 ≥ 50%

**排除标准**:
- 环境占比 > 5% 的主流套牌（如 卢德维佳作寇姆/织命使堤谟娜、持绊逸才季宁）
- 无 Primer 或详细资料可供分析的新牌

### 步骤 6：深度拆解"小屋严选"套牌

每份周报选择 **1–2 套** "小屋严选"套牌进行深度拆解。每套牌的标准分析结构：

```markdown
### X. [套牌中文名]（[英文原名 / 常见简称]）

**赛事成绩**：冠军 @ 比赛名称（人数）/ 或最佳成绩

#### 打法

- 套牌原型（极速组合技 / 中速 Stax / 控制等）
- 核心游戏计划（2–3 句话概括）
- 调度哲学（什么样的起手值得保留）

#### 核心组合技

用表格列出主要组合技线路：

| 无限法术力引擎 | 胜利出口 |
|---|---|
| 组件 A + 组件 B | 胜利手段 |

对每条线路说明：
- 执行步骤（编号列表）
- 是否需要过渡（Pivot）
- 实战技巧（对手可能如何干扰，如何应对）

#### 终结手段

| 终结手段 | 机制 | 优势 |
|---|---|---|
| 手段名称 | 如何杀死对手 | 为什么选它 |

#### 环境定位

- 当前 meta 中的生态位
- 优势对局（克制哪些主流套牌）
- 劣势对局（被哪些牌/策略克制）
- 上手建议（适合什么样的玩家）
```

### 步骤 7：横向对比（如分析多套牌）

如果本期拆解了 2 套以上套牌，增加横向对比表：

```markdown
| 维度 | 套牌 A | 套牌 B |
|---|---|---|
| 颜色 | | |
| 原型 | | |
| 制胜速度 | | |
| 核心资源 | | |
| 学习曲线 | | |
| 反制韧性 | | |
| meta 定位 | | |
| 上手建议 | | |
```

## 五、命名规范

**文件名格式**:
```
cedh-tournament-report-YYYY-MM-DD-to-YYYY-MM-DD.md
```

- 起始日期：报告覆盖周期的第一天（周一）
- 结束日期：报告覆盖周期的最后一天（周日）
- 示例: `cedh-tournament-report-2026-04-07-to-2026-04-21.md`

---

## 六、注意事项

1. **牌名翻译**: 所有套牌名必须使用中文官方译名，通过 `name_translator.py` 或 mtgch API 确认
2. **数据完整性**: 如果某场比赛缺少 Top 16 数据，标记为 "N/A"，不要猜测
3. **分析深度**: "小屋严选"套牌必须结合 Primer 分析，不能仅基于牌表描述
4. **客观性**: 避免主观评价（如"这套牌很强"），用数据和事实支撑结论
5. **时效性**: 周报应在覆盖周期结束后 48 小时内生成发布
