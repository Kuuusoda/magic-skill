# 堆叠推演框架

## 框架定位

当题目涉及**多个咒语/异能在堆叠上的互动**时，使用本框架进行系统性推演。

## 判定步骤

### 步骤1：识别所有进入堆叠的事件

按时间顺序列出所有进入堆叠的咒语/异能：
- 主动施放的咒语
- 起动的异能
- 触发式异能（每个触发事件独立进入堆叠）
- 特殊时机施放的牌（如倾曳、返照等）

### 步骤2：确定堆叠顺序

堆叠遵循**后进先出**（LIFO）原则：
```
堆叠顶部 ← 最后进入
...
堆叠底部 ← 最先进入
```

触发式异能进入堆叠的时机：
- 在触发事件发生后，于**下一次有牌手获得优先权时**进入堆叠
- 多个触发同时发生时，**主动牌手**的触发先放入，然后是**非主动牌手**的触发

### 步骤3：标注优先权传递点

标记每个可以获得优先权并作出响应的时机：
- 施放咒语后（AP 获得优先权，可传递）
- 异能进入堆叠后
- 每个步骤/阶段开始时
- 战斗伤害结算后

### 步骤4：逐步结算

从堆叠顶部开始，逐个结算：
1. **当前牌手**执行结算
2. 结算过程中产生的新触发进入堆叠（在结算完成后）
3. 结算完成后，**主动牌手**获得优先权
4. 若无人响应，继续结算下一个

### 步骤5：检查状态动作

在以下时机检查状态动作：
- 每次有牌手获得优先权时
- 每次结算完成后
- 注意：状态动作**不**使用堆叠，直接执行

## 常见判例

| 案例 | 核心问题 | 结论 |
|------|---------|------|
| 伤害触发后施放瞬间响应 | 触发和响应的堆叠顺序 | 触发先进入堆叠，响应后进入，响应先结算 |
| 多个触发同时发生 | 谁决定堆叠顺序 | 主动牌手的触发先放入，非主动牌手后放 |
| 结算中创建的新触发 | 何时进入堆叠 | 当前物件结算完成后进入堆叠 |
| 状态动作 vs 堆叠 | 状态动作是否使用堆叠 | 不使用堆叠，直接执行 |
