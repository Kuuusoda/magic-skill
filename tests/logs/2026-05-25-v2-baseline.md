## 核心发现

### 1. Pipeline 能正确解析题目
- QueryCompiler Agent 正确提取题目中的卡牌名称（Q1 提取 3 张）
- KnowledgeRetrieval Agent 正确识别关键机制（intervening if、堆叠、触发式异能）

### 2. Checker 过于严格导致 verdict blocked/warning
- 硬检查要求所有 must_have 规则必须存在
- 软检查将分析性评论误认为 gaps
- 虚构卡牌不在本地数据库中，导致"缺少 Oracle 数据"被标记为 gap

### 3. AnswerComposer 在 warning/blocked 时不输出结论
- 即使 verdict=warning，AnswerComposer 仍输出"无法给出确定结论"
- 不输出明确的选项字母（A/B/C/D/E）

### 4. Pipeline 设计为开放式问答，不适合选择题
- 当前架构假设所有牌可在数据库中找到
- 测试题的虚构卡牌不在数据库中
- AnswerComposer 没有选择题模式

## 结论

v2 Pipeline 的核心能力（规则分析、机制识别、证据引用）已具备，但当前架构不适合直接用于多项选择题答题。需要以下改进方可用于测试回归：

1. **Checker 严格度校准**：区分"真正缺失"vs"分析性评论"
2. **虚构卡牌支持**：从题目文本中提取 Oracle 文本作为证据
3. **选择题模式**：AnswerComposer 增加"选择选项字母"的输出格式
